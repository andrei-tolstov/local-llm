# Отчёт: настройка шума и охлаждения пассивной Tesla V100 (18.11.2026)

**Хост:** 192.168.50.38 (Huananzhi X79, E5-2650v2) · **GPU:** Tesla V100-PCIE-32GB (пассивная)
**Охлаждение:** серверный вентилятор на каналах NCT6779 `pwm2` (CPU_FAN) + `pwm3` (SFAN3),
логика ШИМ инвертирована: `255` = минимум оборотов, `0` = 100 %.
**Драйвер:** 550.163.01, CUDA 12.4. Режим GPU во всех тестах: `−pl 250 −lgc 1380` (день).

---

## 1. Что измерялось и чем

| Инструмент | Назначение |
|---|---|
| `scripts/gemm_bench.cu` | непрерывный cuBLAS HGEMM (тензорные ядра) — предельный источник тепла |
| `scripts/gpu_fan_sweep.py` | стенд: ступени ШИМ → ожидание стационарного режима → телеметрия + защита |
| `scripts/llm_load.py` | реальный инференс (prefill 4000 ток. + decode 400 ток.) через API ninfer |

Ключ к интерпретации: **ШИМ инвертирован**, поэтому в таблицах «duty %» = `(255 − PWM)/255`,
то есть **чем больше PWM, тем тише**.

Критерий стационарности: окно 60 с, наклон < 0.2 °C/мин, разброс ≤ 1 °C (тепловая инерция
пассивной карты — стационар наступает через 3–5 мин после смены оборотов).

---

## 2. Главное открытие: настоящий порог троттлинга — 82 °C, а не 87 °C

`nvidia-smi -q -d TEMPERATURE` показывает `GPU Slowdown Temp: 87 C`, но фактически
`SW Thermal Slowdown` включается при **82–83 °C** (это же `GPU Max Operating Temp: 83 C`):

| Ступень | Stationary T | Частота SM | Потребление | Троттлинг |
|---|---|---|---|---|
| 25.5 % duty (PWM 190) | 82.1 °C | 1380 → **1260 МГц** | 135 Вт | `sw_thermal_slowdown` |
| 15.7 % duty (PWM 215) | 82.0 °C | **682–930 МГц** | **72–80 Вт** | `sw_thermal_slowdown` |

То есть на тихих оборотах карта не «греется до 87», а **сбрасывает частоту вдвое и теряет
~55 % производительности уже на 82 °C**. Все пороги кривой обязаны считать 82 °C красной
линией, а рабочий потолок — 74–78 °C.

Пределы карты: ядро `slowdown` 87 °C / `shutdown` 90 °C / фактически 82 °C;
HBM2 `max operating` 85 °C (по замерам отстаёт от ядра на 2–4 °C).

---

## 3. Тепловая характеристика: температура от оборотов (стационар)

Нагрузка 125–142 Вт (GEMM + живой инференс), режим 250 Вт / 1380 МГц:

| duty % | PWM | T ядра | T HBM | Вт | Троттлинг |
|---|---|---|---|---|---|
| 64.7 | 90 | 53.3 | 50.0 | 123 | нет |
| 54.9 | 115 | 55.9 | 52.6 | 126 | нет |
| 52.9 | 120 | 58.9 | 55.2 | 128 | нет |
| 45.1 | 140 | 60.0 | 57.1 | 129 | нет |
| 43.1 | 145 | 63.0 | 59.4 | 135 | нет |
| 35.3 | 165 | 67.9 | 65.0 | 128 | нет |
| 33.3 | 170 | 73.9 | 71.1 | 142 | нет |
| 25.5 | 190 | **82.1** | 79.9 | 135 | **да** |
| 15.7 | 215 | 82.0 (упор) | 79.8 | 75 (сброшен) | **да** |

Аппроксимация (по точкам 64.7→33.3 %): `R_т ≈ 0.182 · (64.7/duty)^0.8 °C/Вт` при
внутрикорпусной температуре ~30 °C. Она же предсказывает 80 °C на 25.5 % (замерено 82.1 °C) —
то есть модель корректна и позволяет считать режимы без замеров:

| Вт на duty | 45 % | 40 % | 35 % | 30 % | 25 % |
|---|---|---|---|---|---|
| 128 Вт | 59 | 63 | 68 | 74 | 80 |
| 165 Вт | 69 | 73 | 79 | 85 ⛔ | — |
| 190 Вт | 75 | 80 ⚠️ | 86 ⛔ | — | — |

**Вывод:** нижняя безопасная граница оборотов под максимальной нагрузкой — **~43–45 % duty**,
под типовым инференсом (110–145 Вт) — **33–41 %**.

## 4. Новая кривая (внедрена)

`scripts/v100_fancontrol.py` → `/usr/local/bin/v100-fancontrol.py`, сервис `v100-fancontrol.service`.

| Условие (`control_t`) | PWM | duty % | Было (v1) |
|---|---|---|---|
| ≤ 48 °C | 205 | 19.6 | 41–51 % (150/125) |
| ≤ 54 | 185 | 27.5 | 41–51 % |
| ≤ 60 | 170 | 33.3 | **64.7 % (90)** |
| ≤ 65 | 150 | 41.2 | 64.7 % |
| ≤ 70 | 140 | 45.1 | **80.4 % (50)** |
| ≤ 74 | 120 | 52.9 | 80.4 % |
| ≤ 78 | 100 | 60.8 | 80.4 % |
| ≤ 80 | 60 | 76.5 | 92.2 % (20) |
| > 80 | 0 | 100 | 100 % (с 75 °C) |

Что ещё исправлено в контроллере:

1. **Гистерезис 4 °C + выдержка 240 с + дебаунс повышения 12 с.** Старая кривая без
   гистерезиса гоняла вентилятор 90 ↔ 125 каждые 30–60 с на простое (слышимое «дыхание»).
2. **Учёт HBM2**: `control_t = max(T_ядра, T_памяти − 3 °C)` (у памяти предел 85 °C).
3. **Потолок по CPU** (`≥70 °C` → не тише PWM 150), т.к. тот же вентилятор обдувает зону CPU/VRM.
4. **Отказоустойчивость**: 3 неудачных опроса `nvidia-smi` → 100 % обдува; при остановке
   сервиса каналы возвращаются в BIOS SmartFan (`enable=5`), SIGTERM/SIGINT обработаны.

### D. Переходные процессы (реакция на наброс нагрузки)

Одиночный GEMM-наброс 100 с (потребление 131 Вт), лог сервиса:

```
22:13:26  gpu=59C -> pwm=185 (27 %) band=1        # начало наброса
22:13:56  gpu=66C -> pwm=150 (41 %) band=3       # +30 с
22:14:27  gpu=67C -> pwm=140 (45 %) band=4       # +60 с, пик 67 °C
22:15:57  gpu=55C -> pwm=140 (45 %)              # нагрузка снята, ступень держится
22:16:4x  gpu=52C -> pwm=185 (27 %)              # спуск после выдержки 150 с
```

Разгон занимает ~60 с, спуск — 2.5–3 мин (выдержка + гистерезис). Качелей нет: в простое
ступень стоит на PWM 185 непрерывно.

Отдельно проверен «холодный» старт демона на уже горячей карте: ступень сразу выбирается
по фактической температуре (52 °C → 27 %), а не с самой тихой; при остановке сервиса ШИМ
фиксируется на `FAILSAFE_PWM = 120` (53 %), а не уходит в BIOS-кривую, которая у этой платы
смотрит только на холодный CPU.

### Оценка шума

Обороты оцениваются по скважности ШИМ (тахометр на NCT6779 не читается:
`fan1..fan5 = 0 RPM`, таховход не подключён). Аэродинамический шум вентилятора
`L ~ n^5`, поэтому `ΔL = 50·log10(n₂/n₁)`:

| Режим | Было | Стало | Δ шума | Мощность вентилятора |
|---|---|---|---|---|
| Простой | 51 % | 27.5 % | **−13 дБ** | в 6.4 раза меньше |
| Инференс | 64.7 % | 33.3 % | **−14.6 дБ** | в 7.5 раза меньше |
| Пиковая нагрузка | 80.4 % | 45.1 % | **−12.4 дБ** | в 5.6 раза меньше |

Производительность GPU не пострадала: частоты 1380 МГц во всех режимах, флагов
троттлинга нет, лимит мощности 250 Вт не менялся.

## 6. Ограничение мощности: нужно ли?

Регулировка оборотов задачу решила — отдельное снижение лимита **не потребовалось**
(текущий профиль: день 250 Вт / 1380 МГц, ночь 23:00 → 100 Вт / 495 МГц).

Тем не менее измерено, какой ценой можно стать ещё тише. Вентилятор зафиксирован на
**25.5 % duty (PWM 190)** — самой тихой ступени, на которой карта ещё что-то считает;
нагрузка GEMM, 5 мин на каждую точку:

| Power Limit | Фактическое потребление | T ядра (стационар) | T HBM | Частота SM | Троттлинг |
|---|---|---|---|---|---|
| 250 Вт | 146 Вт | 80.4 °C (макс 83) | 77.1 | 1380 МГц | `sw_thermal_slowdown` |
| 150 Вт | 143 Вт | 80.9 °C (макс 83) | 78.0 | 1370 МГц | `sw_power_cap` + thermal |
| 120 Вт | 119 Вт | 80.9 °C | 78.6 | **1250 МГц** | нет, но впритык |

**Вывод: лимитом мощности стать ещё тише нельзя.** На 25 % оборотов карта упирается в
81–83 °C даже при 119 Вт (частота при этом уже снижена до 1250 МГц), а лимит 150 Вт вообще
ничего не меняет — реальное потребление GEMM на этой карте 143–146 Вт, то есть лимит 150 Вт
почти не задействован. Разумный нижний предел оборотов:

* типовой инференс (110–145 Вт) → **33 % duty** (73.9 °C, запас 8 °C),
* предельная нагрузка (~150–170 Вт) → **45 % duty** (65 °C, запас 17 °C).

Именно это и делает новая кривая: она сама выбирает минимальную ступень под текущий нагрев,
поэтому профиль «ночной тишины» остаётся прежним (`nvidia-power-night`: 100 Вт + 495 МГц в 23:00),
дополнительные ограничения мощности не требуются. По данным
`power_and_optim/report_benchmark.md` снижение до 130 Вт стоило бы 11.3 % скорости генерации
(46.0 против 51.9 t/s) — при том что шум уже снижен оборотами.

---

## 7. Что делать летом / при росте температуры в корпусе

Кривая температурная, а не «по оборотам»: если в корпусе станет теплее, контроллер сам
поднимет обороты на нужную ступень. Запас заложен в рабочих ступенях (74–78 °C вместо
82 °C). Если при этом вентилятор станет слышимее в пике — это штатное поведение защиты;
профиль тишины в этом случае достигается лимитом мощности (п. 6), а не оборотами.

## 8. Файлы и команды

```bash
# стенд (не останавливать демон вручную — стенд делает это сам и возвращает обратно)
nvcc -O3 -o /tmp/gemm_bench scripts/gemm_bench.cu -lcublas -lcudart
python3 scripts/gpu_fan_sweep.py --pwm 90,115,140,165,190,215 --pl 250 --lgc 1380 \
    --load-cmd "/tmp/gemm_bench 3000 4096 & /tmp/gemm_bench 3000 2048 & wait" \
    --min-duration 180 --steady-window 60 --abort-temp 82.5 --out /tmp/sweep.json

# проверка тепловых ступеней при фиксированной мощности
python3 scripts/gpu_fan_sweep.py --pwm 190 --pl 150 --lgc 1380 ...

# наблюдение за живой кривой под реальной нагрузкой
python3 scripts/gpu_fan_sweep.py --monitor-only --max-duration 420 \
    --load-cmd "python3 scripts/llm_load.py --url http://localhost:8087 --seconds 330"

# диагностика контроллера
python3 /usr/local/bin/v100-fancontrol.py --once      # что выберет кривая сейчас
journalctl -u v100-fancontrol -f                     # ступени в реальном времени
cat /sys/class/hwmon/hwmon1/pwm2                     # фактический ШИМ
```

Перед тестами обязательно: `systemctl pause nvidia-power-night.timer nvidia-power-day.timer`
(и `resume` после), иначе в 23:00 тесты собьются на ночной режим 100 Вт / 495 МГц.
